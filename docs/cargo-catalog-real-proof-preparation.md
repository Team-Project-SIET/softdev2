# Complete native cargo catalog proof preparation

This proof kind is `cargo-catalog`, distinct from the proven single native cargo page. Public entry points are `python -m app.simulation.openttd.proof prepare --mode cargo-catalog` and `preflight --mode cargo-catalog`. Preparation/preflight create no OpenTTD process, live Admin connection or application request. Future `run --mode cargo-catalog --authorize-one-launch` requires fresh explicit authorization against the exact frozen preparation. No wrapper or destination override exists.

The session ID is `openttd15-cargo-catalog-001`; requests are `-p001` through `-p032`, deterministic and distinct. First cursor is null. Every continuation uses the previous next_after_id. Page size stays 2; generic default/max stay 2/4. The first valid terminal page ends collection immediately. A one-page terminal catalog may pass; a nonterminal page cannot claim completeness. No exact total cargo count or set is hard-coded.

Limits: 32 pages/requests, 64 records, 16384 cumulative response bytes, 512 post-authentication Admin subscription/query/control frames. Each query uses the existing transport's operation budget capped at 16 frames (four required operations plus finite room for control/date/other subscribed frames). The recorder separately caps total post-auth traffic at 512, including subscription overhead. Authentication frames are excluded from this query-plane limit. Thus 32 x 16 supplies the session ceiling, while setup overhead may exhaust it earlier; exhaustion fails safely. Every payload remains <=512 bytes and <1450 bytes. A fixed catalog-page request ID has a 154-byte worst-case envelope; two 76-byte records plus one comma give 307 bytes, leaving 205 bytes application headroom. Generic four-record bound remains 493.

Reuse CargoCatalogSession and immutable CargoCatalogObservation. All pages, receipts, ordered IDs and metadata validate before a terminating chain can assemble complete=true. Digest serialization remains unchanged: ascending cargo_id, cargo_label, is_freight, town_effect and the existing V1 normalized class mask. It excludes request IDs, page boundaries, clocks, logs, packet boundaries, paths and localized names. Runtime identity is retained by the model; bridge identity is retained with the proof observation/evidence. Partial observations explicitly retain complete=false and no successful digest claim.

The successful real cargo-page proof is supporting native-binding/profile evidence, not a failure predecessor or an independent catalog source. Exact pinned binary, graphics and generation profile support a nonempty first-page proof rule without an exact cargo-ID expectation. The frozen bridge, native GSCargoList, GSCargo metadata APIs and GSList item/ascending sorting are reused unchanged. No schema expansion. Labels remain native cargo identity within an active cargo/industry set; generic properties should express behavior for NewGRF compatibility. Freight is native freight-weight semantics, not routing policy. Town effect stays structural, not planner policy. Localized GetName, cargo income, production/transport quantities, stockpiles, station acceptance, cargo goals, refit and industry_cargo queries are excluded.

One process and one continuous encrypted X25519 Admin connection are owned by the public CLI and EndpointReservation. Per-page GameScript chain: BRIDGE_REQUEST_RECEIVED → CARGO_PAGE_READ → BRIDGE_RESPONSE_SENT → BRIDGE_POST_RESPONSE_ALIVE. Python chain: CARGO_PAGE_REQUEST_SENT → CARGO_PAGE_RESPONSE_RECEIVED → TRANSPORT_RECEIPT_CREATED → CARGO_PAGE_VALIDATED. Session chain: CARGO_CATALOG_SESSION_STARTED → page validations → FINAL_PAGE_VALIDATED → CARGO_CATALOG_ASSEMBLED → CARGO_CATALOG_VERIFIED → CARGO_CATALOG_SESSION_COMPLETED. Only local order plus typed request/response digest/cursor correlation is required; no total cross-process clock ordering.

Lifecycle: PREPARED → LAUNCHED → ADMIN_ACTIVE → CATALOG_SESSION_STARTED → FINAL_PAGE_VALIDATED → CATALOG_ASSEMBLED → CATALOG_VERIFIED → COMPLETED, or FAILED. Repeated pages belong to child evidence. Timeout, disconnect, connection replacement or ambiguity fail the session; no retry, resume, reconnect, resend or relaunch. Completed and in-flight response/receipt evidence survives failure. Cleanup stops/reaps the process, checks endpoint closure and removes the credential. Fresh private key is mode 0600 and excluded from public evidence. No gameplay mutation or RCON.

Exact historical path/hash authority and archived credential identities protect every captured historical root. Cargo-catalog lineage only acknowledges matching proof-kind PRELAUNCH failures whose immutable evidence proves 0/0/0, with a newer freeze and fresh authorization. Unknown relevant failure evidence blocks; runtime failure cannot use this exception; no force/ignore switches.

Independent second-source cargo catalog: NONE. Industry capability equivalence: NOT PROVEN BY THIS SLICE. Production history: NOT INCLUDED. P08 completion: NO. Complete native catalog traversal/assembly await separately authorized execution. Existing controlled capability/catalog referential validation remains available, but historical runs are not combined into a same-run world proof.
