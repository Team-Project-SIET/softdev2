# Terrain paired evidence v1

Status: contract specification for CONTROLLED implementation, 2026-10-10.
Identifier `terrain-paired-evidence-v1`; integer version `1`. This is a separate
package contract, not a revision of the documented
[baseline-1](openttd-offline-evidence-freeze.md). It implements retention for the
[approved equality design](p08-two-sweep-equality-design.md) and respects the
[bounded regional plan](p08-multi-page-terrain-acquisition.md).

## Scope and trust

Only CONTROLLED evidence is representable. Exact mode is `CONTROLLED`; acceptance
is `CONTROLLED_PAIRED_EVIDENCE_ACCEPTED`, never REAL_PASS. No operator authorization,
process, endpoint, credentials, cleanup, GameScript log or native session is asserted.
The package proves byte integrity relative to supplied authority and reproducible
semantic admission of recorded exchanges, not that observations occurred in OpenTTD.
Equal sweeps do not establish an atomic snapshot. A region contains 1..256 tiles;
256 tiles are partial coverage of a 64×64 map.

No baseline-1 artifact, source commitment, policy, validator or historical record
changes. Historical native REAL_PASS remains supported. Historical complete offline
acceptance remains AUDIT_BLOCKED with 13 missing canonical inputs. No missing bytes
are reconstructed.

## Encoding and scalar rules

Reuse `app.planning.canonical.canonical_bytes` on strict frozen contract models.
That helper accepts `BaseModel` trees, not raw dictionaries or dataclasses.
Convert the existing dataclass context/budgets through explicitly declared strict
models, and validate derived metadata dictionaries into strict nested summary
models before encoding. The dataset-identity object also has its own small strict
model. Never pass `pair.metadata` or an arbitrary dictionary directly to this helper.
JSON uses UTF-8, sorted object keys, compact separators, no NaN, no trailing newline;
ordered arrays retain their order. Reject duplicate JSON keys, unknown/missing
fields, incorrect types and noncanonical metadata bytes. Integer fields reject
booleans. Digests are 64 lowercase hexadecimal SHA256 characters; hashes cover exact
bytes, not parsed/reformatted payloads. Reuse existing protocol request/response
serialization and parsers for application bytes. Responses need not have canonical
JSON formatting: their exact bytes are retained and hashed.

The existing `TerrainDataset.metadata.rows_sha256` remains the row-digest authority:
compact ASCII JSON of the full ordered ten-field row tuple. Do not replace it with a
planning projection or a second row-normalization algorithm.

## Descriptor schema

`package.json` has exactly these fields:

| Field | Required value or structure |
| --- | --- |
| schema | `terrain-paired-evidence-v1` |
| version | integer 1 |
| mode | `CONTROLLED` |
| status | `COMPLETE`, `INCOMPLETE` or `FAILED` |
| context | acquisition_id, world_fingerprint, map_width, map_height, region |
| budgets | per_sweep and combined objects below |
| sweeps | ordered array of exactly two sweep records |
| artifacts | ordered array of exact retained artifact commitments |
| failure | null for COMPLETE; otherwise {code, message} with nonempty bounded strings |

`context.region` is exactly `{x,y,width,height}`, validated as existing `Region`.
Other context fields construct `TerrainSweepContext`; the longest request identifier
must validate. Fingerprint is a declared controlled source identity, not a native
fingerprint extracted from a response and not a hash of terrain rows.

Each sweep record has exactly `{identity, pages}`. Identity is
`{acquisition_id, ordinal}` with ordinals 1 then 2 and the same acquisition ID as
context. COMPLETE pages enumerate every planned page; other statuses may retain
only the ordered admitted prefix, with sweep two empty unless sweep one is complete.
Each page has exactly `{ordinal, request_id, cursor, tile_ids, request_artifact,
response_artifact, exchange_artifact}`. Page ordinal starts at 1 independently per
sweep. Request IDs are `<acquisition_id>-s<S>-p<PPP>` as generated by pagination.
Coverage identities derive from context and cursor, never from this index alone.

Each artifact commitment has exactly `{path, byte_length, sha256}`. Entries are
unique and sorted by ASCII path. They commit summary and all three files per
retained page, excluding `package.json` itself and the deterministic manifest.
The external descriptor digest binds this entire array plus context, budgets,
status and both ordered sweep indexes. No self-referential digest is needed.

## Exact artifact inventory

For a complete package with `P=ceil(N/5)`:

| Path | Presence and content |
| --- | --- |
| package.json | Required canonical descriptor |
| summary.json | Required canonical derived results |
| artifact-manifest.sha256 | Required deterministic consistency manifest |
| pages/s1/p001/request.json … pages/s1/pPPP/request.json | Exact protocol request bytes |
| pages/s1/p001/response.json … pages/s1/pPPP/response.json | Exact protocol response bytes |
| pages/s1/p001/exchange.json … pages/s1/pPPP/exchange.json | Receipt, observed context and exchange accounting |
| pages/s2/p001/{request,response,exchange}.json … pages/s2/pPPP/{request,response,exchange}.json | Independent second-sweep evidence |

There are no optional artifacts in v1. Expected directories are only `pages`,
`pages/s1`, `pages/s2` and the required `pPPP` directories; reject unexpected empty
directories too. All files must be regular files, not symlinks. Reject aliases,
traversal, absolute paths, backslashes, alternate case, duplicate/conflicting paths,
noncanonical numbering and special file types. Resolve below the supplied package
root; reject a symlink root or intermediate symlink. Use established ownership
conventions: package files are durable retained evidence; external originals are
never deletion targets. Require a quiescent package while verifying, use no-follow
reads and hash/replay the same bytes to avoid a check/read substitution. Do not
silently search for or read artifacts outside the package.

The authoritative inventory is generated from validated context, status and page
plan and compared with both the descriptor and actual recursive inventory. The
mutable manifest never authorizes files. Its format reuses harness conventions:
`<sha256><two spaces><relative path><LF>`, ASCII-path sorted, every file except the
manifest itself. Unlike `harness.manifest()`, which is top-level-only, v1 enumeration
must cover the explicit nested inventory; do not change that baseline helper.

Resource bounds for v1: descriptor <=131,072 bytes, summary <=65,536 bytes,
exchange metadata <=4,096 bytes/page, request <=159 bytes and response <=508 bytes.
At 104 pages, indexed metadata/payload bounds total <=691,960 bytes before the
manifest. At most 315 files are permitted. Including a manifest bounded to 65,536
bytes, total retained bytes must be <=1,048,576. These limits bound reads before
JSON parsing. They are package safety limits, not native runtime limits.

## Exchange and summary records

`exchange.json` has exactly `{observed_context, receipt, ordered_sequence,
protocol_operations, requests_sent, matching_responses, retries}`.
Observed context has the descriptor context shape and must equal it at admission.
Receipt has exactly existing `TileFactsReceipt` fields: request_id,
request_payload_sha256 and response_payload_sha256. Rebuild the frozen receipt and
exchange, converting the sequence array to a tuple. Require existing
`TileFactsExchange.validate()` semantics: exact lifecycle sequence, one request,
one matching response, no retries and recorded operation count 4..8. Those counts
are validated records, not independently measured native transport events.

For COMPLETE, `summary.json` has exactly `{dataset_identity, pair_metadata}`.
`pair_metadata` must equal canonicalized `VerifiedTerrainPair.metadata` after replay,
including both sweep metadata objects, page coverage, row digests and actual byte/
operation totals. It is a redundant checkable summary, not acceptance authority.
`dataset_identity` is SHA256 of canonical bytes of exactly
`{policy:"terrain-paired-dataset-v1", context:<context>, rows_sha256:<row digest>}`.
It identifies the immutable semantic dataset and declared context; package digest
separately identifies receipts, budgets and exact bytes. No stored `equal=true`
field is permitted or needed.

For INCOMPLETE/FAILED, summary is exactly `{accepted:false, received_pages:<two
arrays of admitted request IDs>}`; descriptor failure message <=1,024 characters,
code <=64 safe ASCII characters. Such packages retain bounded diagnostics, cannot
produce an accepted dataset and are not verified successful failure attestations.
The successful verifier rejects non-COMPLETE status explicitly. No automatic retry,
resume, missing-page fabrication or promotion from diagnostics is allowed.
The first implementation's writer accepts only verified complete pairs. Diagnostic
writer support is deferred; these status shapes establish fail-closed dispatch
without requiring another writer interface or claiming validated failure evidence.

## Independent commitment authority

Proposed public verifier interface:
`verify_paired_package(directory, *, expected_descriptor_sha256) -> VerifiedTerrainPair`.
The expected digest is mandatory and supplied separately from package data.
No overload reads an expected digest from `package.json`, a sidecar inside the
package, its manifest or an automatically discovered sibling file.

In CONTROLLED mode, the caller establishing the test/review record is the authority.
It accepts and verifies the in-memory pair, runs the writer, and independently
computes SHA256 of the finalized canonical `package.json`. It pins that digest in
its trusted test input or reviewed external record before any mutation or transfer.
The writer may return a calculated digest for comparison, but its output alone is
not verifier authority. The authority controls its expected value and must not
recompute it from a challenged package. In a fresh process, pass the pinned value
explicitly through a trusted invocation argument/configuration chosen by that
caller. This authenticates no human or operator; trust in the caller and verifier
code is an explicit prerequisite.

The descriptor digest commits artifact paths, exact lengths/hashes, both ordered
indexes, source context and selected budgets. These bind all page bytes through
SHA256 commitments. Manifest bytes are not independently authorized; their exact
expected bytes are derived from the committed descriptor and descriptor bytes,
then compared with the retained manifest. Changing either page bytes or descriptor
and regenerating the manifest cannot bypass an unchanged independent commitment.
Missing/invalid expected digest rejects. An attacker who controls that external
value can authorize another semantically valid controlled dataset; cryptography
cannot protect against replacement of its own trust anchor.

After writing, the package is complete and not appended. Replacing it produces a
new commitment, not an update accepted under the old one. Deleting original
candidate/test workspaces has no effect: all observations and contexts needed for
replay are retained. Verifier source and the independently supplied digest remain
external authorities; original temporary paths and baseline historical roots are
not dependencies of this CONTROLLED data package. No source provenance, native
process ownership or credential-disposal claims are imported from baseline-1.

## Budgets

| Configured ceiling | Per sweep | Combined |
| --- | ---: | ---: |
| Pages | 52 | 104 |
| Request bytes/page | 159 | 159 unchanged |
| Response bytes/page | 508 | 508 unchanged |
| Request bytes | 8,268 | 16,536 |
| Response bytes | 26,416 | 52,832 |
| Recorded query operations | 416 | 832 |

Per-sweep keys exactly match `PaginationBudget`: max_pages, page_request_bytes,
page_response_bytes, max_request_bytes, max_response_bytes, max_operations.
Combined keys exactly match `TwoSweepBudget`: max_pages, max_request_bytes,
max_response_bytes, max_operations. All are exact positive integers at or below
existing ceilings. Smaller configured limits remain committed and enforced.
Preflight required page counts; sum actual application payload lengths and validated
exchange counters without resetting combined consumption between sweeps. Measured
bytes exclude framing/encryption. These caps do not certify AdminPort session
lifetime, getter counts, authentication, frame counts or native timeout behavior.

## Validation order and replay

1. Require independently supplied, well-formed expected digest and safe package root.
   Read bounded descriptor bytes and compare SHA256 before trusting its contents.
2. Strictly parse canonical metadata, dispatch exact schema/version/mode and reject
   unsupported identifiers. Reject non-COMPLETE status at the success boundary.
3. Reconstruct context/budgets and independently generate two request plans. Validate
   sweep/page identities, expected artifact paths and all declared commitment entries.
4. Compare exact recursive inventory/types; read bounded authorized files once.
   Verify committed lengths and SHA256 and the exact derived manifest.
5. Parse exchange metadata strictly and reconstruct each receipt/exchange. Validate
   request bytes against planned identity; page echoes, geometry and receipt digests
   must validate through existing protocol code, not descriptor claims.
6. Create `TerrainTwoSweep` with committed context and budgets. In sweep order,
   admit each exchange using its recorded observed context and sweep identity;
   call `complete_sweep()` after each complete sweep. This reuses private
   `TerrainPagination` admission for coverage, order, budgets and terminal cursors.
7. Call `finish()`. It requires complete equal full rows, monotonic date brackets and
   both independently complete sweeps. Compare all ten fields: tile, minimum height,
   slope, occupancy flags, industry, owner, road0, outgoing, incoming, assessed.
8. Compare replay-derived summary and dataset identity exactly; return only the frozen
   paired result. Exceptions reject; no partial accepted output.

Failures have stable categories for commitment, schema, inventory, bytes, exchange,
replay and summary. Preserve causes when wrapping expected parsing/validation
exceptions; do not broadly catch unexpected programming errors. The in-memory
`VerifiedTerrainPair` constructor alone is not verifier authority: writer invokes
its existing `verify()` before finalizing evidence.

## Behavior test matrix

Every negative test starts with a valid full-path package; preserve unrelated
prerequisites. For semantic challenges, the controlled authority deliberately pins
a newly generated descriptor for that invalid test fixture, so integrity checks
pass and semantic replay is tested. This is a test authority, not forged historical
or genuine operator authorization. Keep unchanged authority for substitution attacks.

| Case | Expected boundary and result |
| --- | --- |
| Complete 1/5/6/255/256-tile pair | Full replay accepts CONTROLLED only |
| Missing/wrong external commitment | Commitment gate rejects |
| Substitute artifact, regenerate mutable manifest | Byte commitment rejects |
| Change descriptor too, unchanged trusted digest | Descriptor commitment rejects |
| Missing/extra file or empty directory | Exact inventory rejects |
| Symlink, traversal, directory/file substitution | Path/type validation rejects |
| Cross-sweep/cross-package page substitution | Commitment rejects; newly committed inconsistent fixture rejects identity/replay |
| Changed world/region context | Existing sweep/protocol identity validation rejects |
| Missing/duplicate/out-of-order page | Plan/index or real pagination rejects exact coverage violation |
| Valid-schema changed terrain field in sweep two | Real equality validation rejects drift |
| Invalid receipt/digest/sequence/counter | Exchange validation rejects |
| False stored byte/page/operation totals | Replayed summary comparison rejects |
| Invalid selected budgets or per-page/sweep/aggregate overflow | Budget construction or admission rejects |
| Changed retained bytes with unchanged receipt and refreshed artifact commitments | Existing receipt validation rejects |
| Valid partial final page | Exact complete coverage accepts |
| INCOMPLETE/FAILED status | Success-status gate rejects, no dataset |
| Delete permitted temporary fixture originals; new cwd/process | Explicit pinned digest + retained package accepts |
| Unsupported schema/version, REAL classification | Strict dispatch rejects, no fallback |
| Existing single-page package | Existing verifier behavior and baseline digests unchanged |

## Implementation sequence

1. Add `app/simulation/openttd/terrain_paired_evidence.py` and
   `tests/test_terrain_paired_evidence.py`. No generic artifact framework or baseline
   changes. Model only descriptor, page metadata and summary; reuse existing frozen
   context/budgets/exchanges. Writer accepts a verified pair and an empty owned output
   directory, writes exclusively, and finalizes descriptor/manifest last. A failed
   write never becomes COMPLETE acceptance.
2. TDD the caller-pinned commitment, deterministic writer, exact inventory and byte
   validation. Gate: valid complete package and recomputed-manifest attack.
3. TDD production replay and summary consistency without mocking acceptance validators.
   Gate: all semantic/budget/coverage tests reach their intended boundary.
4. Test cleanup independence, fresh process and baseline compatibility. Gate: no
   original temporary reads, secrets or authority inferred from mutable package data.
5. Run focused/ordinary regressions with real-native deselected, lint/format/type/import/
   diff/history checks and independent Spec/Standards review before controlled acceptance.

## Native integration requirements

A future native package needs separately reviewed immutable source provenance,
Model A authorization/claim lineage, authenticated session identity, multi-request
log ranges and lifecycle correlation, measured frame accounting, getter/static
bounds, deadlines, endpoint/process cleanup, credential disposal and exact native
artifact inventory. This CONTROLLED version provides none of those claims and must
not be promoted to REAL by changing a mode field. Native extension/version approval
and exact one-shot execution authorization are separate future gates.
